# HU-ARQ-02 — Backend MVP

Spring Boot + PostgreSQL API for the Synkro Tech MVP. One process, one schema.
Consumed directly by the frontend (HU-FE-01) — there are no mocks, so **check
with the frontend before changing any response shape below**.

- Java 21, Spring Boot 4.1.1, Spring Data JPA, Bean Validation
- Base URL: `http://localhost:8080`
- CORS: `http://localhost:5173` and `http://127.0.0.1:5173`

## Running it

The database lives in the existing `my-database` container (port 5435 → 5432).
Create the schema once if it isn't there yet:

```bash
docker exec my-database psql -U postgres -c "CREATE DATABASE synkrotech_db;"
```

Then, from `backend/`:

```bash
./mvnw spring-boot:run
```

Hibernate creates the tables (`ddl-auto=update`, no Flyway for this spike) and
`DataSeeder` fills empty tables with 3 users, 3 customers, 3 categories and
7 products. Seeding is skipped whenever a table already has rows, so restarts
never duplicate data.

## Conventions

- **Ids are UUIDs**, generated by the application.
- **Nothing is ever hard-deleted.** `PATCH .../deactivate` flips `active` to
  false so past sales keep resolving. Deactivated rows still come back from the
  list endpoints; add `?active=true` to hide them.
- **Money is a decimal with 2 places** (`price`, `unitPrice`, `subtotal`,
  `total`) and is serialised as a JSON number.
- **Dates are ISO-8601 strings** without a timezone, e.g. `2026-08-29T21:41:46.335`.
- **Uniqueness is scoped to active rows.** A customer's `taxId` and a category's
  `name` must be unique among *active* records only; deactivating one frees the
  value for reuse.

### Error shape

Every failure returns the same body:

```json
{
  "timestamp": "2026-08-29T21:41:40.918",
  "status": 409,
  "error": "Conflict",
  "message": "An active customer already uses the tax id 999888777-1.",
  "fieldErrors": null
}
```

| Status | When |
| ------ | ---- |
| `400` | Bean Validation failed. `fieldErrors` maps each bad field to its message. Also malformed JSON or an unparseable UUID. |
| `404` | The id in the **path** does not exist. |
| `409` | A domain rule was broken: duplicate tax id / category name, not enough stock, deactivated customer or product, unknown id **in a request body**. |

`message` is always safe to show to the user as-is.

## Endpoints

### Auth (simulated — no password, no token)

The `users` table only powers a login picker. `POST /login` echoes the chosen
user back; the frontend keeps it in memory as the current session.

| Method | Path | Body | Returns |
| ------ | ---- | ---- | ------- |
| `GET` | `/api/auth/users` | — | `[{id, name, role}]`, active users only |
| `POST` | `/api/auth/login` | `{"userId": "<uuid>"}` | `{id, name, role}` |

`role` is one of `ADMIN`, `SALESPERSON`, `INVENTORY`.
Unknown `userId` → `404`; deactivated user → `409`.

### Customers

| Method | Path | Body | Returns |
| ------ | ---- | ---- | ------- |
| `GET` | `/api/customers` | — | all customers, by name. `?active=true` filters |
| `GET` | `/api/customers/{id}` | — | one customer |
| `POST` | `/api/customers` | `CustomerRequest` | `201` + the customer |
| `PUT` | `/api/customers/{id}` | `CustomerRequest` | the updated customer |
| `PATCH` | `/api/customers/{id}/deactivate` | — | the deactivated customer |

`CustomerRequest`: `name` and `taxId` are required; `email` (must look like an
address), `phone` and `address` are optional.

```json
{
  "id": "a50a1435-...", "name": "Distribuidora El Roble", "taxId": "900123456-1",
  "email": "compras@elroble.co", "phone": "3001112233",
  "address": "Cra 5 #12-40, Neiva", "active": true
}
```

### Categories

| Method | Path | Body | Returns |
| ------ | ---- | ---- | ------- |
| `GET` | `/api/categories` | — | `[{id, name, active}]`. `?active=true` filters |
| `POST` | `/api/categories` | `{"name": "Periféricos"}` | `201` + the category |

### Products

| Method | Path | Body | Returns |
| ------ | ---- | ---- | ------- |
| `GET` | `/api/products` | — | all products, by name. `?active=true` filters |
| `GET` | `/api/products/{id}` | — | one product |
| `POST` | `/api/products` | `ProductRequest` | `201` + the product |
| `PUT` | `/api/products/{id}` | `ProductRequest` | the updated product |
| `PATCH` | `/api/products/{id}/deactivate` | — | the deactivated product |

`ProductRequest`: `name`, `price` (**> 0**, max 2 decimals), `stock` (**>= 0**)
and `categoryId` are all required. An unknown or deactivated `categoryId` → `409`.

The response carries `categoryName` alongside `categoryId` so a list can be
rendered without a second call:

```json
{
  "id": "8f2d52c4-...", "name": "Teclado mecánico RGB", "price": 189900.00,
  "stock": 25, "categoryId": "6f00db48-...", "categoryName": "Periféricos",
  "active": true
}
```

### Sales

| Method | Path | Body | Returns |
| ------ | ---- | ---- | ------- |
| `GET` | `/api/sales` | — | history, newest first |
| `GET` | `/api/sales/{id}` | — | one sale |
| `POST` | `/api/sales` | see below | `201` + the created sale |

```json
{
  "customerId": "a50a1435-...",
  "items": [{ "productId": "8f2d52c4-...", "quantity": 3 }]
}
```

`items` must not be empty and every `quantity` must be `>= 1`.

Creating a sale runs in a single transaction:

1. The customer must exist and be active.
2. Every product must exist, be active, and have enough stock.
3. Each product's current `price` is copied into the line's `unitPrice` — **frozen**,
   so later price changes never rewrite what was charged.
4. Stock is deducted per line. Listing the same product twice is fine; the
   second line is checked against the stock left after the first.
5. `subtotal = quantity × unitPrice`, and `total` is their sum.

If any check fails the response is `409` with a message naming the product, and
**nothing is persisted** — stock deducted for earlier lines is rolled back.

```json
{
  "id": "cb0f4e4b-...", "customerId": "a50a1435-...",
  "customerName": "Distribuidora El Roble",
  "date": "2026-08-29T21:41:46.335", "total": 4500.00, "active": true,
  "items": [{
    "id": "69a2e62c-...", "productId": "8f2d52c4-...",
    "productName": "Teclado mecánico RGB",
    "quantity": 3, "unitPrice": 1500.00, "subtotal": 4500.00
  }]
}
```

## Layout

```
com.synkrotech.mvp
  common/     shared error types + the @RestControllerAdvice that renders them
  config/     CORS for the Vite dev server, startup data seeding
  auth/       User, Role, login picker
  customers/  Customer CRUD + soft delete
  products/   Category and Product CRUD + soft delete
  sales/      Sale, SaleDetail, and the stock/pricing rules.
              Calls the customers and products services directly — same
              process, no HTTP. That comes later, with the real microservices.
```

`spring.jpa.open-in-view` is **off**: each read fetches the associations it
serialises (see the `join fetch` queries in `ProductRepository` and
`SaleRepository`), so a lazy-loading mistake fails loudly in development
instead of quietly holding a database connection open for the whole request.
